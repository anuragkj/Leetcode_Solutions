## Original Problem

You are given a string s consisting of lowercase English letters.

In one operation, you can select any substring of s that is not the entire string and sort it in non-descending alphabetical order.

Return the minimum number of operations required to make s sorted in non-descending order. If it is not possible, return -1.

Example 1:

Input: s = "dog"

Output: 1

Explanation:​​​​​​​

- Sort substring "og" to "go".

- Now, s = "dgo", which is sorted in ascending order. Thus, the answer is 1.

Example 2:

Input: s = "card"

Output: 2

Explanation:

- Sort substring "car" to "acr", so s = "acrd".

- Sort substring "rd" to "dr", making s = "acdr", which is sorted in ascending order. Thus, the answer is 2.

Example 3:

Input: s = "gf"

Output: -1

Explanation:

- It is impossible to sort s under the given constraints. Thus, the answer is -1.

Constraints:

- 1 <= s.length <= 10^5

- s consists of only lowercase English letters.

**Examples / sample tests:**

```
"dog"
"card"
"gf"
```

## Problem Summary
Given a string `s` of lowercase English letters, we can sort any *proper* substring (not the entire string) in non-descending order. The goal is to find the minimum number of operations to make the entire string `s` sorted alphabetically. If it's impossible, return -1.

## Intuition
The core constraint is that we **cannot sort the entire string** in one operation. This means the characters at the very beginning (`s[0]`) and very end (`s[n-1]`) of the string have a special status. They can only be changed if they are part of a *proper* substring that is sorted. For example, `s[0]` can change if we sort `s[0:k]` for `k < n`, and `s[n-1]` can change if we sort `s[k:n]` for `k > 0`.

Let `target_s` be the string `s` with its characters sorted alphabetically. Our goal is to transform `s` into `target_s`.

We can analyze the problem by considering the number of operations:

*   **0 Operations:** If `s` is already sorted (i.e., `s == target_s`), no operations are needed.
*   **-1 Operations:** If the string length `n` is 1, it's always sorted (covered by 0 ops). If `n` is 2 and `s` is not sorted (e.g., "ba"), we can only sort `s[0:1]` (just `s[0]`) or `s[1:2]` (just `s[1]`). Neither changes the string, so it's impossible to sort.
*   **1 Operation:** This is possible if either `s[0]` is already the smallest character in `s` (i.e., `s[0] == target_s[0]`) OR `s[n-1]` is already the largest character in `s` (i.e., `s[n-1] == target_s[n-1]`).
    *   If `s[0] == target_s[0]`, we can sort the suffix `s[1:n]`. This is a proper substring (since `n > 1`). After sorting, `s[0]` remains `target_s[0]`, and `s[1:n]` becomes `target_s[1:n]`, resulting in `target_s`.
    *   Similarly, if `s[n-1] == target_s[n-1]`, we can sort the prefix `s[0:n-1]`. This is a proper substring. After sorting, `s[n-1]` remains `target_s[n-1]`, and `s[0:n-1]` becomes `target_s[0:n-1]`, resulting in `target_s`.
*   **2 Operations:** This applies when `s[0] != target_s[0]` AND `s[n-1] != target_s[n-1]`, but it's not the special "swapped ends" case (described below).
    The strategy is to first fix one end, then the other. For example:
    1.  Find the smallest character (`target_s[0]`) in `s`. Let its current index be `k`. Sort the prefix `s[0:k+1]`. This moves `target_s[0]` to `s[0]`. This is a valid operation because `k+1 < n` (if `k+1 == n`, it means `target_s[0]` is at `s[n-1]`, which is the 3-op case).
    2.  Now `s[0]` is correct. The problem reduces to the 1-operation case. Sort the suffix `s[1:n]` to fix the rest of the string.
*   **3 Operations:** This is a specific edge case when `s[0] != target_s[0]` AND `s[n-1] != target_s[n-1]`, AND the smallest character `target_s[0]` is currently at `s[n-1]`, AND the largest character `target_s[n-1]` is currently at `s[0]`. (e.g., `s = "cba"`, `target_s = "abc"`). In this "swapped ends" scenario, a 2-operation strategy won't work because fixing one end often displaces the other end in a way that requires another step. A known sequence of three proper substring sorts can resolve this.

## Approach
The solution follows a case-by-case analysis based on the string's length and the positions of its smallest and largest characters.

1.  **Calculate Length and Target:**
    *   Get the length of the input string `s`, denoted as `n`.
    *   Create `target_s` by sorting the characters of `s` alphabetically and joining them back into a string.

2.  **Base Case: Already Sorted:**
    *   If `s` is already equal to `target_s`, it means no operations are needed. Return `0`.

3.  **Edge Case: Small Strings:**
    *   If `n` is 1, the string is always sorted (covered by step 2).
    *   If `n` is 2 and `s` is not sorted (e.g., "ba"), it's impossible to sort using proper substrings (as `s[0:1]` and `s[1:2]` are single characters and sorting them does nothing). Return `-1`.

4.  **One Operation Case:**
    *   Check if `s[0]` is already the smallest character (`target_s[0]`) OR `s[n-1]` is already the largest character (`target_s[n-1]`).
    *   If either condition is true, we can sort the remaining part of the string in one operation (e.g., `s[1:n]` if `s[0]` is correct, or `s[0:n-1]` if `s[n-1]` is correct). Return `1`.

5.  **Three Operations Case (Swapped Ends):**
    *   This case occurs when `s[0]` is *not* `target_s[0]` AND `s[n-1]` is *not* `target_s[n-1]`.
    *   Specifically, check if `s[0]` is equal to `target_s[n-1]` (the largest character) AND `s[n-1]` is equal to `target_s[0]` (the smallest character). This is the "swapped ends" scenario.
    *   If this pattern holds (e.g., "cba" where `target_s` is "abc"), it requires `3` operations. Return `3`.

6.  **Two Operations Case (Remaining):**
    *   If none of the above conditions are met, it implies `s[0]` is not `target_s[0]` AND `s[n-1]` is not `target_s[n-1]`, AND it's not the "swapped ends" pattern.
    *   In this scenario (e.g., "card"), `2` operations are sufficient. Return `2`.
