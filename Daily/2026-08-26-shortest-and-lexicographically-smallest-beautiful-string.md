## Original Problem

You are given a binary string s and a positive integer k.

A substring of s is beautiful if the number of 1's in it is exactly k.

Let len be the length of the shortest beautiful substring.

Return the lexicographically smallest beautiful substring of string s with length equal to len. If s doesn't contain a beautiful substring, return an empty string.

A string a is lexicographically larger than a string b (of the same length) if in the first position where a and b differ, a has a character strictly larger than the corresponding character in b.

- For example, "abcd" is lexicographically larger than "abcc" because the first position they differ is at the fourth character, and d is greater than c.

## Problem Summary
Given a binary string `s` and an integer `k`, we need to find a substring that contains exactly `k` ones. Among all such "beautiful" substrings, we want the one with the **shortest length**. If there are multiple shortest beautiful substrings, we choose the one that is **lexicographically smallest**. If no beautiful substring exists, return an empty string.

## Intuition
This problem asks us to find a substring with a specific property (exactly `k` ones) and then optimize it based on two criteria: length and lexicographical order. A classic technique for finding substrings that satisfy certain conditions is the **sliding window** approach.

Here's how we can think about it:
1.  **Finding `k` ones**: We can use a window defined by `left` and `right` pointers. As we move the `right` pointer, we expand the window and count the number of '1's inside it.
2.  **Exactly `k` ones**: When our window contains exactly `k` ones, we've found a "beautiful" substring.
3.  **Shortest length**: Once we have `k` ones, we want to make the substring as short as possible. We can achieve this by trying to shrink the window from the `left` side. If `s[left]` is '0', removing it doesn't change the count of '1's, so the window remains beautiful and becomes shorter. If `s[left]` is '1', removing it would reduce the count of '1's to `k-1`, making the window no longer beautiful. So, we can only shrink from the left as long as `s[left]` is '0' or if `s[left]` is '1' and we are okay with `current_ones` dropping below `k` (which we are, to continue expanding `right`). The key is that *while* `current_ones == k`, we have a beautiful substring, and we should try to make it shorter by moving `left`.
4.  **Lexicographically smallest**: We need to keep track of the shortest length found so far (`min_length`) and the corresponding string (`result_string`). When we find a new beautiful substring:
    *   If it's shorter than `min_length`, it becomes the new best.
    *   If it has the same length as `min_length`, we compare it lexicographically with `result_string`. If the new one is smaller, it becomes the new best.

This combination of expanding the window with `right` and conditionally shrinking with `left` (while maintaining `k` ones) allows us to efficiently find all potential beautiful substrings and keep track of the best one according to the problem's criteria.

## Approach
We will use a **sliding window** approach with two pointers, `left` and `right`.

1.  **Initialization**:
    *   `n`: Length of the input string `s`.
    *   `left`: Initialize to `0`, representing the start of our current window.
    *   `current_ones`: Initialize to `0`, to count '1's in the current window `s[left...right]`.
    *   `min_length`: Initialize to `float('inf')` to keep track of the shortest beautiful substring length found so far.
    *   `result_string`: Initialize to an empty string `""`, to store the lexicographically smallest beautiful substring of `min_length`.

2.  **Expand Window (Move `right` pointer)**:
    *   Iterate `right` from `0` to `n-1`.
    *   For each `s[right]`: if it's '1', increment `current_ones`.

3.  **Shrink Window (Move `left` pointer) and Update Result**:
    *   **While `current_ones == k`**: This means the current window `s[left...right]` is a beautiful substring.
        *   Extract the `current_sub = s[left : right + 1]`.
        *   Calculate its `current_len = len(current_sub)`.
        *   **Compare with current best**:
            *   If `current_len < min_length`: This new substring is shorter. Update `min_length = current_len` and `result_string = current_sub`.
            *   Else if `current_len == min_length`: This new substring has the same length. Compare lexicographically: if `current_sub < result_string`, update `result_string = current_sub`.
        *   **Attempt to shrink from left**: To find potentially shorter beautiful substrings ending at the current `right` position, we try to move `left` forward.
            *   If `s[left] == '1'`: Decrement `current_ones`. (This will make `current_ones` less than `k`, breaking the `while` loop, as the window is no longer beautiful).
            *   Increment `left`. (This effectively shrinks the window).
            *   If `s[left]` was '0', `current_ones` remains `k`, and the `while` loop continues, allowing us to check the newly shortened beautiful substring.

4.  **Return Result**: After iterating through all possible `right` positions, `result_string` will hold the desired substring. If no beautiful substring was found, `result_string` will remain `""`.

```python
class Solution:
    def shortestBeautifulSubstring(self, s: str, k: int) -> str:
        n = len(s)
        left = 0
        current_ones = 0
        
        min_length = float('inf')
        result_string = "" # Stores the lexicographically smallest beautiful substring of min_length
        
        for right in range(n):
            # Expand the window by moving the right pointer
            if s[right] == '1':
                current_ones += 1
            
            # While the window s[left...right] has exactly k ones, it's a beautiful substring.
            # We try to shrink it from the left to find the shortest one ending at 'right'.
            while current_ones == k:
                current_sub = s[left : right + 1]
                current_len = len(current_sub)
                
                # Check if this substring is better than our current best
                if current_len < min_length:
                    # Found a shorter beautiful substring
                    min_length = current_len
                    result_string = current_sub
                elif current_len == min_length:
                    # Found a beautiful substring of the same length
                    # Compare lexicographically to find the smallest
                    if current_sub < result_string:
                        result_string = current_sub
                
                # Shrink the window from the left.
                # If s[left] is '1', current_ones will become k-1, breaking the while loop.
                # If s[left] is '0', current_ones remains k, and the loop continues,
                # allowing us to find an even shorter beautiful substring ending at 'right'.
                if s[left] == '1':
                    current_ones -= 1
                left += 1
                
        return result_string

```

## Why This Works
This sliding window approach works because it systematically explores all possible beautiful substrings and correctly applies the two-stage optimization criteria (shortest length, then lexicographically smallest).
The `right` pointer ensures that every possible ending position for a substring is considered. The `while current_ones == k` loop, combined with incrementing `left`, ensures that for *each* `right` position, we find the **shortest possible beautiful substring ending at `right`**. This is crucial because any beautiful substring `s[i:j]` can be shortened to `s[i':j]` (where `i' > i`) if `s[i:j]` contains leading '0's or if `s[i]` is a '1' and `s[i+1:j]` still contains `k` ones. Our `while` loop effectively prunes these longer, less optimal substrings. By comparing `current_len` first and then `current_sub` lexicographically, we guarantee that `result_string` always holds the best candidate found so far according to the problem's rules. If no beautiful substring is ever found, `result_string` remains `""`, correctly handling that edge case.
