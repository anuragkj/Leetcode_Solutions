## Original Problem

You are given an integer array coins representing coins of different denominations and an integer k.

You have an infinite number of coins of each denomination. However, you are not allowed to combine coins of different denominations.

Return the k^th smallest amount that can be made using these coins.

## Problem Summary
We are given a list of coin denominations and an integer `k`. We can use an infinite number of coins of any single denomination, but we cannot combine coins of *different* denominations. The goal is to find the `k`-th smallest distinct amount that can be formed.

## Intuition
This problem asks for the "k-th smallest" value, which is a classic indicator for **Binary Search on the Answer**. If we can efficiently determine how many distinct amounts are less than or equal to a given value `X`, we can binary search for the smallest `X` such that this count is at least `k`.

The core challenge then becomes: how to count the number of distinct amounts less than or equal to `X`?
Each coin `c` can form multiples `c, 2c, 3c, ...`. The set of all possible amounts is the **union** of the multiples generated by each coin. For example, if `coins = [3, 5]`, the amounts are `{3, 5, 6, 9, 10, 12, 15, ...}`.
To count the size of a union of sets, the **Inclusion-Exclusion Principle** is the standard technique.
For sets `M_1, M_2, ..., M_N` (multiples of `c_1, ..., c_N` respectively):
`|M_1 U ... U M_N| = Sum(|M_i|) - Sum(|M_i ∩ M_j|) + Sum(|M_i ∩ M_j ∩ M_l|) - ...`
An amount is in `M_i` if it's a multiple of `c_i`. The number of multiples of `c_i` up to `X` is `floor(X / c_i)`.
An amount is in `M_i ∩ M_j` if it's a multiple of both `c_i` and `c_j`, which means it's a multiple of their **Least Common Multiple (LCM)**. So, `|M_i ∩ M_j|` is `floor(X / lcm(c_i, c_j))`.
This generalizes: for any subset of coins, say `{c_{s1}, c_{s2}, ..., c_{sp}}`, their intersection corresponds to multiples of `lcm(c_{s1}, c_{s2}, ..., c_{sp})`. The count is `floor(X / lcm(c_{s1}, ..., c_{sp}))`.
The sign (add or subtract) depends on the number of coins in the subset: add for odd-sized subsets, subtract for even-sized subsets.
Since `coins.length` is small (up to 15), we can iterate through all `2^N` subsets of coins using bit manipulation.

## Approach
1.  **Binary Search Range:**
    *   The smallest possible amount is `1` (or `min(coins)`). So, `low = 1`.
    *   A safe upper bound for the `k`-th smallest amount is `k * max(coins)`. Given `k <= 2 * 10^9` and `max(coins) <= 25`, this upper bound can be `5 * 10^{10}`. So, `high = k * max(coins)`.

2.  **`count_amounts(limit)` Function:** This function calculates the number of distinct amounts less than or equal to `limit`.
    *   Initialize `total_count = 0`.
    *   Iterate through all non-empty subsets of `coins` using a bitmask from `1` to `2^N - 1` (where `N = len(coins)`).
    *   For each bitmask `i`:
        *   Initialize `current_lcm = 1` and `num_elements = 0`.
        *   Iterate through `coins[j]` for `j` from `0` to `N-1`:
            *   If the `j`-th bit is set in `i` (meaning `coins[j]` is in the current subset):
                *   Increment `num_elements`.
                *   Calculate `lcm(current_lcm, coins[j])`. Use the formula `lcm(a, b) = (a * b) // gcd(a, b)`.
                *   **Crucial Optimization:** If `current_lcm` becomes greater than `limit` at any point, it means `floor(limit / current_lcm)` will be `0`. We can cap `current_lcm` at `limit + 1` (or simply `break` from the inner loop) to avoid further large number calculations and potential overflow if Python wasn't handling arbitrary precision integers. The `_lcm` helper function handles this capping.
        *   After calculating `current_lcm` for the subset:
            *   If `current_lcm` is still `> limit` (meaning it was capped), this subset contributes `0`. Continue to the next subset.
            *   Otherwise, apply the Inclusion-Exclusion Principle:
                *   If `num_elements` is odd, add `floor(limit / current_lcm)` to `total_count`.
                *   If `num_elements` is even, subtract `floor(limit / current_lcm)` from `total_count`.
    *   Return `total_count`.

3.  **Binary Search Loop:**
    *   Initialize `ans = high` (our best candidate for the `k`-th smallest amount).
    *   While `low <= high`:
        *   Calculate `mid = low + (high - low) // 2`.
        *   Call `count_amounts(mid)`.
        *   If `count_amounts(mid) >= k`: This `mid` could be our answer, or we might find a smaller one. Store `mid` in `ans` and try searching in the lower half: `high = mid - 1`.
        *   Else (`count_amounts(mid) < k`): `mid` is too small; we need a larger amount. Search in the upper half: `low = mid + 1`.
    *   Return `ans`.

## Complexity
*   **Time Complexity:** `O(log(K * max(coins)) * 2^N * N)`
    *   The binary search performs `log(MAX_AMOUNT)` iterations, where `MAX_AMOUNT` is roughly `k * max(coins)`. For `k = 2 * 10^9` and `max(coins) = 25`, `MAX_AMOUNT = 5 * 10^{10}`, so `log_2(5 * 10^{10})` is approximately `56`.
    *   The `count_amounts` function iterates through `2^N` subsets (where `N = coins.length`). `N <= 15`, so `2^15 = 32768`.
    *   For each subset, it iterates through up to `N` coins to calculate their LCM. Each `_lcm` operation involves `math.gcd`. The numbers involved in `gcd` are `current_lcm` (which can be up to `MAX_LCM_OF_COINS`, approximately `2.3 * 10^8` for numbers up to 25) and `coins[j]` (up to 25). `gcd` for such numbers is very fast (effectively constant time in competitive programming contexts, or `O(log(MAX_LCM_OF_COINS))` if considering bit length).
    *   Total operations: `56 * 32768 * 15` which is approximately `2.7 * 10^7`. This is well within typical time limits.

*   **Space Complexity:** `O(N)`
    *   This is for storing the `coins` array and the recursion stack for `math.gcd` (if not iterative). The bitmask approach does not use extra space proportional to `2^N`.

## Edge Cases
*   **`coins.length = 1`**: The inclusion-exclusion principle simplifies to just `floor(limit / coins[0])`, which the code handles correctly.
*   **`k = 1`**: The binary search will correctly find `min(coins)` as the 1st smallest amount.
*   **`coins` contains `1`**: If `1` is a denomination, any positive integer can be formed. `count_amounts(limit)` will return `limit` (since `floor(limit/1)` dominates). The binary search will then correctly return `k`.
*   **`coins` contain multiples of each other (e.g., `[3,6,9]`)**: The inclusion-exclusion principle naturally handles this by adding and subtracting terms that cancel out, ensuring only distinct amounts are counted. For `[3,6,9]`, the union of multiples is simply the multiples of `3`.
*   **Large `k` and `max(coins)`**: The `high` bound for binary search (`k * max(coins)`) is chosen to accommodate the largest possible answer (`5 * 10^{10}`), and Python's arbitrary-precision integers handle these large values without overflow.

## Solution

```python
import math
from typing import List

class Solution:
    def findKthSmallest(self, coins: List[int], k: int) -> int:
        N = len(coins)

        # Function to count distinct amounts <= limit using inclusion-exclusion
        def count_amounts(limit):
            # Helper function to calculate LCM for two numbers, capping at 'limit'.
            # If the LCM exceeds 'limit', it returns 'limit + 1' to signify "too large".
            # This prevents intermediate overflow and ensures the result doesn't exceed 'limit'.
            def _lcm(a, b):
                if a == 0 or b == 0: 
                    return 0 # Should not happen with coins[i] >= 1
                
                # If 'a' is already effectively infinity, it stays infinity.
                # Also, if 'b' is 1, LCM is 'a'. If 'a' is 1, LCM is 'b'.
                # These are handled by the general formula, but good to keep in mind.
                
                common_divisor = math.gcd(a, b)
                
                # Check if a * (b / common_divisor) would exceed 'limit'.
                # This is equivalent to checking if a > limit / (b / common_divisor).
                # This check is crucial for preventing overflow and capping the LCM.
                # Note: b // common_divisor will not be zero since coins[i] >= 1.
                if b // common_divisor > limit // a:
                    return limit + 1
                
                return (a // common_divisor) * b

            total_count = 0
            # Iterate through all non-empty subsets using bitmasks
            # A bitmask 'i' from 1 to 2^N - 1 represents a subset.
            # If the j-th bit is set in 'i', coins[j] is in the subset.
            for i in range(1, 1 << N): 
                current_lcm = 1
                num_elements = 0
                
                # Build the subset and calculate its LCM
                for j in range(N):
                    if (i >> j) & 1: # If j-th coin is in the subset
                        num_elements += 1
                        
                        # Calculate lcm(current_lcm, coins[j])
                        # The _lcm function handles capping at 'limit'.
                        current_lcm = _lcm(current_lcm, coins[j])
                        
                        # Optimization: if LCM already too big, its contribution is 0.
                        # Break early from inner loop for this subset.
                        if current_lcm > limit: 
                            break 
                
                # If LCM became too large during calculation, its contribution is 0.
                if current_lcm > limit:
                    continue

                # Apply inclusion-exclusion principle:
                # Add for odd-sized subsets, subtract for even-sized subsets.
                if num_elements % 2 == 1:
                    total_count += (limit // current_lcm)
                else:
                    total_count -= (limit // current_lcm)
            return total_count

        # Binary search for the k-th smallest amount
        # The smallest possible amount is 1.
        # The largest possible amount is k * max(coins).
        # For k = 2 * 10^9 and max(coins) = 25, this is 5 * 10^10.
        # Python's integers handle this magnitude automatically.
        low = 1
        high = k * max(coins) 
        ans = high # Initialize with a value that is definitely an upper bound

        while low <= high:
            mid = low + (high - low) // 2
            
            # Check if 'mid' can form at least 'k' distinct amounts.
            if count_amounts(mid) >= k:
                ans = mid       # 'mid' is a possible answer, try for a smaller one.
                high = mid - 1
            else:
                low = mid + 1   # 'mid' is too small, need a larger amount.
        
        return ans

```

## Why This Works
The solution leverages two powerful techniques: **Binary Search** and the **Inclusion-Exclusion Principle**.
1.  **Monotonicity for Binary Search**: The function `count_amounts(x)` (which counts distinct amounts less than or equal to `x`) is monotonically non-decreasing. If `x` increases, the number of amounts less than or equal to `x` can only stay the same or increase. This monotonicity is the fundamental property that allows binary search to efficiently find the `k`-th smallest `x`.
2.  **Correct Counting with Inclusion-Exclusion**: The `count_amounts` function correctly calculates the size of the union of sets of multiples for each coin. By iterating through all subsets of coins and applying the alternating sum of `floor(limit / lcm_of_subset)`, it precisely determines the number of *distinct* amounts up to `limit`. The `lcm` capping optimization ensures correctness and efficiency when dealing with potentially very large numbers.
By combining these, the binary search iteratively narrows down the range until it finds the smallest `x` for which `count_amounts(x)` is at least `k`, which is precisely the `k`-th smallest amount.
